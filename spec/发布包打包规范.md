# WinClaw2 全量更新发布包规范

这是通过更新服务器发布 WinClaw2 Windows x64 版本时的打包准则。源代码、协议和验收规则见 `winclaw2-full-update.md`。

## 产物

在 `D:\winclaw2\winclaw2` 构建正式身份 NSIS 安装器后，运行 `node scripts/winclaw-package-update.mjs`。输出目录 `packages/desktop/dist/winclaw2-update/` 必须包含：

```text
release.json
WinClaw-2.x.y-win-x64.exe
latest.yml                 只用于本地核对，不直接上传覆盖线上清单
上传说明.md
```

`release.json` 包含版本、`cn.hoardsun.winclaw2` 正式身份、Windows x64、`nsis-full`、EXE 文件名和字节数、SHA512 Base64、解包体积、构建提交、构建时间及更新说明。生成脚本重算 EXE 的实际大小和 SHA512；服务端上传时再核对一次。

发布版本使用 `2.x.y`。同一版本一经发布即不可替换字节；重新构建或修复必须增加补丁版本。preview/stable 是发布指针，不通过安装包文件名或 `-preview` 版本后缀区分。

发布包**只含完整安装器**；不收集 `.blockmap`、增量包、Web 安装器、旧 Python runtime 包或旧版 `winclaw-update.json`。

## 发布顺序

1. 核对正式产品身份、应用版本、构建提交及完整 EXE；在隔离 Windows 机器上安装和启动。
2. 打开管理页面，选择 `release.json` 与同目录 EXE。等待上传及 SHA512 校验完成；此时版本仅标记“可发布”。
3. 发布到 preview，从较低 `2.x` 安装版本验证完整下载、重启安装、数据及 helper 保留。
4. 预览验收通过后，把**同一个 releaseId** 提升 stable。不要重新签名、压缩或改动 EXE。
5. 通过两个渠道的清单和安装包 URL 检查版本、绝对地址、大小与 SHA512；记录发布 revision。

历史 `3.14.x` 因数字版本较高，首次改用 `2.x` 必须手动覆盖安装并验证数据兼容。后续 `2.x` 使用自动更新。撤回通道只阻止后续升级；已安装坏版本用更高补丁版本的完整包修复。

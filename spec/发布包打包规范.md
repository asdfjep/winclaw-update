# 发布包打包规范（WinClaw 自动更新）

> 本文件是 **WinClaw 自动更新发布包** 的唯一权威打包准则。
> 之后的 WinClaw 对话 LLM / 开发助手在"打包 / 打发布包 / 发布版本 / 生成安装包"时，
> 必须先读本文件并**严格遵循**。人类运维同守。

**适用对象**：所有通过自动更新分发（服务器 `10.233.129.67:8091`）发布的 WinClaw 桌面端版本。

---

## 1. 发布包由三部分构成

| 文件 | 说明 |
|------|------|
| `Hs-WinClaw-Setup-<版本>.exe` | **瘦安装包**（程序内容 + 技能，**不含** Python 等运行环境） |
| `winclaw-update.json` | 更新清单（版本 / 安装包哈希 / **runtimes 环境包列表**） |
| `runtimes/runtime-python-<stamp>.zip` | 环境包（当前为 Python 3.12 离线包）。按 stamp 共享，不随每次内容更新重复下载 |

产物统一落在仓库 `installer/` 目录。

> 安装包不再内嵌 `python-offline` / `python/`。客户端**每次登录后**检查本地环境；缺失则从更新平台 ` /update/runtimes/` 拉取。
> **每次打包必须附带当前需要的环境包**（见第 5 节）。更新平台上传 zip 后会**自动分流**环境包到共享仓库，清单里的安装包只负责内容更新。

---

## 2. 命名规范（强制）

- 安装包文件名：**必须**是 `Hs-WinClaw-Setup-<版本>.exe`，例如 `Hs-WinClaw-Setup-1.6.2.exe`。
- 环境包文件名：**必须**是 `runtime-<id>-<stamp>.zip`，当前 Python 为 `runtime-python-3.12.10-1.zip`（stamp 来自 `tools/python-offline/stamp`）。
- 更新管理端靠 exe 文件名推断版本号，写错就没法识别。
- 打成 zip 交付给管理端时，zip 内直接放：exe + `winclaw-update.json` + `runtimes/` 目录。

> ⚠️ **严禁**产出 `Hs-WinClaw-Setup-<版本>-update-package.zip` 这类"文件名 + 裸 exe"的伪 zip。
> 它根本不是 zip（开头是文件名文本，真正的 PK 压缩头在偏移 512 处），管理端/任何 zip 工具都会解析失败。
> 2026-08-20 已踩坑：上传 `Hs-WinClaw-Setup-1.4.2-update-package.zip` → 「zip 解析失败：不是有效的 zip 文件」。

---

## 3. zip 打包的正确方式

标准 zip 的特征 = 文件首 4 字节 `PK\x03\x04`（`50 4B 03 04`）。生成方式二选一：

```powershell
# 方式 A：PowerShell（Windows 自带）
Compress-Archive -Path installer\Hs-WinClaw-Setup-<版本>.exe, installer\winclaw-update.json, installer\runtimes `
                 -DestinationPath installer\WinClaw-<版本>-发布包.zip -CompressionLevel Optimal
# 方式 B：7-Zip 命令行
7z a "installer\WinClaw-<版本>-发布包.zip" "installer\Hs-WinClaw-Setup-<版本>.exe" "installer\winclaw-update.json" "installer\runtimes"
```

打包后先自检：`xxd -l 4`（或记事本/压缩软件打开）确认是 zip，不是别的东西。zip 内应能看到 `runtimes/runtime-python-*.zip`。

---

## 4. 清单字段要求（winclaw-update.json）

```json
{
  "version": "1.6.2",
  "url": "http://10.233.129.67:8091/update/Hs-WinClaw-Setup-1.6.2.exe",
  "sha256": "与 exe 实际哈希一致（小写 hex）",
  "notes": "- 每条更新说明一行，客户端更新弹窗原样展示",
  "mandatory": false,
  "publishedAt": "2026-09-10",
  "runtimes": [
    {
      "id": "python",
      "stamp": "3.12.10-1",
      "file": "runtime-python-3.12.10-1.zip",
      "url": "http://10.233.129.67:8091/update/runtimes/runtime-python-3.12.10-1.zip",
      "sha256": "与环境包 zip 实际哈希一致（小写 hex）",
      "size": 12345678
    }
  ]
}
```

- `url` 前缀**必须**是 `http://10.233.129.67:8091/update`（更新服务器）。
  历史上曾误写 `10.233.129.65`（Git 服务器）导致客户端 404。
- 安装包 `sha256` 必须 = 对应 exe 的 SHA-256（小写），否则客户端校验失败会中止更新。
- `runtimes[]` **必填**：登录检查靠它下载缺失环境。缺此项时新安装无法准备 Python。
- `runtimes[].stamp` 必须与客户端内置 `PythonRuntime.RuntimeStamp` / `tools/python-offline/stamp` 一致。
- `notes` 建议直接取 git 提交历史（`tools/gen_update_manifest.ps1` 自动生成）。

## 5. 出包流程（优先走构建脚本，不做手工）

1. 确认 `tools/python-offline/` 齐全（`python-3.12.10-embed-amd64.zip`、`get-pip.py`、`wheels/`、`stamp`）。缺失时先跑 `tools\bundle_python.ps1 -SkipLocalExtract`。
2. 构建瘦安装包：运行仓库根 `build_installer.bat` → 产出 `installer\Hs-WinClaw-Setup-<版本>.exe`（**不**拷贝 python-offline 进安装包）。
3. 生成清单与环境包：构建脚本自动调用 `tools\gen_update_manifest.ps1`
   - 计算 exe SHA256
   - 把 `tools/python-offline` 打成 `installer\runtimes\runtime-python-<stamp>.zip`
   - 写入带 `runtimes[]` 的 `installer\winclaw-update.json`
4. 清点产物：exe + json + `runtimes/runtime-python-*.zip` 齐全；清单 version 与 exe 一致；两个 sha256 分别对得上 exe 和环境包。
5. 如需整包上传：按第 3 节打成**标准 zip**（必须含 `runtimes/`）。

## 6. 发布 / 回滚（更新管理端）

- 管理地址：`http://10.233.129.67:8091`（端口 8091，非 8081）。
- 上传：拖拽标准 zip（含环境包）。服务端会：
  1. 保存瘦安装包（按版本）
  2. **自动分流** `runtimes/*.zip`（以及 zip 内若带有 `python-offline/` 目录也会打包）到卷内 `/runtimes/` 共享仓库（同 stamp 去重）
  3. 「设为发布」时把**全部已分流环境包**写入 `winclaw-update.json.runtimes`
- 只上传裸 exe 也可以：内容更新仍生效，环境包沿用平台上已有的共享包。但**平台上还没有环境包时禁止只传 exe**。
- **设为发布**：列表里点目标版本「设为发布」→ 服务端原子写 `winclaw-update.json` → 客户端在 24h 检查周期内自动更新内容包；环境缺失则登录时另下。
- **回滚**：把旧版本重新「设为发布」即可。
- **删除**：只能删非当前发布版本；共享环境包不随版本删除。

## 7. 上传前自检清单（发布者逐项确认）

- [ ] exe 文件名 = `Hs-WinClaw-Setup-<版本>.exe`（瘦包，不含 python-offline）
- [ ] `installer\runtimes\runtime-python-<stamp>.zip` 存在，stamp 与 `tools/python-offline/stamp` 一致
- [ ] zip（若用）= 标准 zip（PK 头），内含 exe + winclaw-update.json + runtimes/
- [ ] `winclaw-update.json` 的 version 与 exe 一致，且含非空 `runtimes[]`
- [ ] 安装包 url / 环境包 url 都是 `http://10.233.129.67:8091/update/...`（`.67`，不是 `.65`）
- [ ] 两个 sha256 分别 = exe、环境包 zip 的实际哈希
- [ ] 上传管理端后，`curl http://10.233.129.67:8091/update/winclaw-update.json` 返回新版本号且带 `runtimes`
- [ ] `curl -I http://10.233.129.67:8091/update/runtimes/runtime-python-<stamp>.zip` 返回 200
- [ ] 无把测试/半成品包留在当前发布位置；测完用旧版本重发布恢复

---

## 8. 客户端行为（供对照）

1. 用户登录成功（含会话恢复）后做环境检查。
2. 本地 `%APPDATA%\Hs-WinClaw\runtime-packs\python` 或已解压的 Python 已就绪 → 跳过下载。
3. 缺失或 stamp 不匹配 → 拉清单 `runtimes[]` 中 `id=python` 且 stamp 匹配的包 → SHA256 校验 → 解压 → 安装到 `%APPDATA%\Hs-WinClaw\python`。
4. 应用内自动更新仍只下载瘦 `Hs-WinClaw-Setup-*.exe`；环境包只在缺失时下载。

---

## 9. 关键约束速查（易错点）

- 更新服务器 = `10.233.129.67:8091`（`.67`）；Git 服务器 = `10.233.129.65:8800`（不要混用）。
- 管理端端口 = `8091`（`8081` 已被宿主机 python 服务占用）。
- **禁止**把 `tools/python-offline` 再打进 Inno 安装包。
- **禁止**发布缺少 `runtimes[]` 的清单（新安装会登录后无法准备 Python）。
- 伪 zip（`-update-package.zip`）禁止作为上传交付物。
- 已发布的旧安装包若内置过 `.65`，需靠新版本覆盖升级或手动改安装目录 `appsettings.json`。
